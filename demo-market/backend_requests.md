## Задача 1. Данни на демото + нов шаблон за нощното възстановяване

Фронтът на demo-market се прави по визията на pavilionbg и е с марка **„Демо Маркет“**.
Данните по-долу са в базата на проекта и се сменят от бекенда със собствения му достъп

### 1.1 SEO на страниците: „PavilionBG“ → „Демо Маркет“

Всичките 21 страници (`pages` id 1–19, 35, 106) имат марката на Pavilion в `seo_title` /
`seo_description`. Проверено с `GET pages?id=N` за всяка. Замени навсякъде в `seo_title`,
`seo_description` и `seo_tags`:

- `PavilionBG` → `Демо Маркет`
- `Pavilion` → `Демо Маркет`

Пример: `Вход в профила | PavilionBG` → `Вход в профила | Демо Маркет`;
`Влез в профила си в PavilionBG, …` → `Влез в профила си в Демо Маркет, …`.

Изключение: началната страница (id `1`, slug `homepage`) е с марката два пъти. Там:

| Поле | Сега | Ново |
|---|---|---|
| `seo_title` | `Pavilion – онлайн пазар с проверени търговци \| PavilionBG` | `Демо Маркет – онлайн пазар с проверени търговци` |
| `seo_description` | (общ текст без марка) | без промяна |

Ако някоя страница не е с точно тези думи, приложи същото правило: марката става „Демо Маркет“,
а останалият текст не се пипа.

## Задача 2. Бъг: `GET products?only_image=1` → SQL грешка, отпечатана сурово

**Статус:** Готово (2026-11-23)

- Филтърът сочеше `t.id`, а псевдонимът на продуктите е `p`. Поправено в ядрото
  (`Product::get_all()`) и в override-а на kokoauto, който имаше същото копие. `only_image=1`
  вече връща JSON (в demo-market и 1447-те продукта са със снимка, затова бройката не се мени).
- Суровият `print_r` е умишлено дебъгване на **дев** ядрото (`devcore.myexpozy.com`): там
  SQL грешката се отпечатва със заявката. На продукционното ядро не се отпечатва, а се записва
  в лога. Остава така.

```
GET https://devcore.myexpozy.com/api/products?limit=2&only_image=1
Authentication: Basic <saas_key на demo-market>
```

Отговорът не е JSON, а PHP `print_r` на изключението, заедно с пътя на файла на сървъра:

```
Array
(
    [message] => mysqli_sql_exception Object
        (
            [message:protected] => Unknown column 't.id' in 'WHERE'
            [code:protected] => 1054
            [file:protected] => /home/d…
```

Без `only_image` същата заявка работи (1447 продукта). Сигурно е в ядрото (`Product::get_all()`),
а не само в demo-market. Провери и в друг проект.

Очаквано:
1. `only_image=1` филтрира продуктите със снимка (параметърът е в `core-v4-front.md` → `GET products`).
2. Грешка в SQL никога не се отпечатва сурово (без пътища и без `print_r`). Връща се стандартното
   `{ "status": 0, "error": "…" }` / `{ "errors": [...] }` с HTTP 500.

Фронтът на demo-market засега не ползва `only_image`.
