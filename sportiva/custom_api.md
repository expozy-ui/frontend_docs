# sportiva — публично API за фронтенда

SPORTIVA.bg — спортен портал (новини, резултати, програма и класиране от
българския футбол). Само на български.

Фронтендът НЯМА собствена база. Всичко минава по HTTP към ядрото (devcore).
Този документ описва какво връща ядрото и как се вика. Поддържа се заедно с
кода — при промяна по endpoint се обновява и тук, в същата стъпка.

Тук са само endpoint-ите на проекта (`sportiva_*`) и ядрените, които проектът
променя. Останалите ядрени endpoint-и са в `core-v4-front.md` в корена на
това repo.

---

## 1. Свързване

```
База (дев):  https://devcore.myexpozy.com/api/
```

Всяка заявка носи хедър, който казва **кой проект** е:

```
Authentication: Basic <saas_key>
```

`saas_key` е един за проекта и се взима от собственика му — не стои в това
repo. Кой проект се обслужва се определя от него, а не от домейна — един и
същ URL на ядрото обслужва всички проекти.

За действия от името на потребител се добавя и:

```
Authorization: Bearer <token>
```

Публичните endpoint-и по-долу минават само със `saas_key`.

## 2. Новини — аудио и видео

```
GET /blogPosts
GET /blogPosts/<id>
GET /blogPosts?category_id=18
```

Всичко е като в ядрото (`core-v4-front.md`) — пагинация, филтри, структура на
публикацията. Списъкът е `{ "result": [...], "pagination": {...} }`.
Добавени са три полета — на всеки елемент от `result` в списъка и на самия
обект при `/<id>`:

```jsonc
{
  "id": 130,
  "title": "Треньорът след мача",
  "cid": 18,
  // … всички ядрени полета
  "audio": {
    "id": 4,
    "object_id": 130,
    "filename": "audio_130_1792570330.m4a",
    "url": "https://r2.expozy.com/sportiva/blog_audio/130/audio_130_1792570330.m4a",
    "path": "sportiva/blog_audio/130/audio_130_1792570330.m4a",
    "date_created": "2026-10-29 12:00:00"
  },
  "videos": [
    { "id": 7, "blog_id": 130, "url": "https://youtu.be/…", "sort": 0, "date_created": "2026-10-29 12:00:00", "date_updated": null }
  ],
  "video_files": [
    {
      "id": 3,
      "object_id": 130,
      "filename": "e166a08cdbf1870e0024090d85ad0a51.mp4",
      "size": 48211374,
      "url": "https://r2.expozy.com/sportiva/sportiva/blog_video_files/130/e166a08cdbf1870e0024090d85ad0a51.mp4",
      "path": "sportiva/blog_video_files/130/e166a08cdbf1870e0024090d85ad0a51.mp4",
      "date_created": "2026-10-29 12:00:00"
    }
  ]
}
```

Публикация без аудио и видео (така изглеждат всички засега):

```json
"audio": { "id": 0, "object_id": 0, "filename": "", "url": "", "path": "", "date_created": "" },
"videos": [],
"video_files": []
```

| Поле | Тип | Значение |
|---|---|---|
| `audio` | object | аудио файлът на новината — **винаги е обект**. Няма ли аудио, `audio.id` е `0`, а `url` е празен низ — проверявай `audio.id`, не дали полето съществува |
| `audio.url` | string | директен адрес на файла — слага се в `<audio src>`. Форматите са mp3, m4a, aac, wav, ogg, opus, webm |
| `videos` | array | видео линковете — **празен** масив, когато няма. Подредени са по `sort` |
| `videos[].url` | string | адресът, както е въведен (YouTube, Facebook и т.н.). **Плейърът го вгражда фронтът** — сървърът не прави embed линк |
| `video_files` | array | качените видео файлове — **празен** масив, когато няма. Подредени по реда на качване |
| `video_files[].url` | string | директен адрес на файла — слага се в `<video src>`. Форматите са mp4, mov, m4v, webm. mov от iPhone (HEVC) не се пуска в Chrome — затова админът е подканен да качва mp4 |
| `video_files[].size` | int | размер в байтове — за надпис като „48 MB", ако трябва |

Категорията **не** казва дали новината има аудио или видео — тя е спортът /
първенството, избрано от редактора. За плейъра гледай `audio.id`, `videos` и
`video_files`. Новина може да има и аудио, и линкове, и файлове
едновременно — покажи всичко.

Грешки: няма нови — неизвестен `id` връща празен обект с `"id": 0`, както в
ядрото.

## 3. Първенства

```
GET /sportiva_leagues               → активните първенства, по sort
GET /sportiva_leagues?in_menu=1     → само тези за менюто
GET /sportiva_leagues?type_id=1     → само първенствата (без купата)
GET /sportiva_leagues/<id>          → едно първенство
```

Публичен — само `saas_key`. Списъкът е **чист масив** (без пагинация —
първенствата са 8). Неактивните не идват в списъка; по `id` идват.

Всяко поле от обекта работи и като филтър (`?category_id=14`,
`?level=3`). Текстовите полета се търсят по частично съвпадение.

```json
{
  "id": 1,
  "title": "efbet Лига",
  "short_title": "efbet Лига",
  "slug": "efbet-liga",
  "type_id": 1,
  "goal_code": "1000000",
  "category_id": 12,
  "level": 1,
  "sort": 1,
  "in_menu": 1,
  "status_id": 1,
  "date_created": "2026-10-29 14:38:33",
  "date_updated": null,
  "url": "https://sportiva.expozy.net/bg/league/1-efbet-liga",
  "logo": { "id": 0, "object_id": 0, "filename": "", "sort_order": 0, "date_created": "", "url": "", "url_10x10": "" },
  "groups": [
    { "id": 1, "league_id": 1, "season_id": 1, "goal_group": "1000000/100", "name": "Първа фаза", "sort": 1, "status_id": 1, "date_created": "2026-10-29 14:38:33", "date_updated": null },
    { "id": 2, "league_id": 1, "season_id": 1, "goal_group": "1000000/211", "name": "Втора фаза, Първа група", "sort": 2, "status_id": 1, "date_created": "2026-10-29 14:38:33", "date_updated": null }
  ]
}
```

| Поле | Тип | Значение |
|---|---|---|
| `title` | string | пълното име — „Североизточна Трета лига" |
| `short_title` | string | кратко име за тесни места — менюто, лентата с мачове („Трета лига СИ") |
| `slug` | string | латиница, за адреса |
| `type_id` | int | `1` — първенство (има класиране), `2` — купа (няма класиране) |
| `category_id` | int | блог категорията с новините на първенството — `GET /blogPosts?category_id=<това>` |
| `level` | int | ниво: `1` — най-горното (efbet Лига, Женско първенство), `2` — Втора лига, `3` — Трети лиги, `0` — купата |
| `sort` | int | редът в менюто и списъците |
| `in_menu` | int | `1` — показва се в мега менюто |
| `url` | string | готовият адрес на страницата на първенството: `/bg/league/{id}-{slug}` |
| `logo` | object | логото — **винаги е обект**; няма ли лого, `logo.id` е `0` и `url` е празен |
| `logo.url` / `logo.url_10x10` | string | оригиналът и малкото копие |
| `groups` | array | групите **за текущия сезон**, по реда им. Първенство без фази има една група с празно `name`. Купата няма групи |
| `groups[].name` | string | надписът на групата — „Първа фаза", „Втора фаза, Първа група". Празно — първенството е без фази |
| `goal_code`, `groups[].goal_group` | string | служебни — кодът в източника на резултатите. Не се показват |

Групите се поддържат автоматично — при нова фаза или нов сезон се появяват
сами. Класирането и мачовете (идват в следващите етапи) ще са **към група**,
затова при efbet Лига покажи групите като табове.

Сегашните първенства:

| `id` | Първенство | `category_id` |
|---|---|---|
| 1 | efbet Лига | 12 |
| 2 | Втора лига | 13 |
| 3 | Североизточна Трета лига | 14 |
| 4 | Северозападна Трета лига | 14 |
| 5 | Югозападна Трета лига | 14 |
| 6 | Югоизточна Трета лига | 14 |
| 7 | Купа на България (`type_id` 2) | 15 |
| 8 | Женско първенство | 19 |

Не хардкодвай id-тата — вземай ги от списъка. Таблицата е за ориентир.

## 4. Отбори

```
GET /sportiva_teams                  → активните отбори, по име, с пагинация
GET /sportiva_teams?title=Левски     → търсене по име
GET /sportiva_teams?city=София       → по град
GET /sportiva_teams/<id>             → един отбор
```

Публичен — само `saas_key`. Списъкът е с пагинация, като блога:
`{ "result": [...], "pagination": {...} }`, `?page=2&limit=20`.

> **Засега списъкът е празен.** Отборите се създават автоматично при вноса
> на мачовете и класирането — следващият етап. Схемата по-долу е
> окончателна.

| Поле | Тип | Значение |
|---|---|---|
| `title` | string | името на сайта |
| `short_title` | string | кратко име за тесни места („Локо Пд") |

| `capacity` | int | места на стадиона; `0` = няма данни |
| `founded` | string | както е въведено — година или пълна дата („1914", „24 май 1914 г.") |
| `titles` / `cups` | int | шампион на България / носител на Купата — брой пъти; `0` = няма или няма данни |
| `description` | string | кратка история, обикновен текст; може да е празен |
| `external_id`, `external_name`, `wikidata_id` | | служебни — от източниците на данни. Не се показват |

Неизвестен `id` връща празен обект с `"id": 0`.

## 5. Сезони

```
GET /sportiva_seasons                → всички сезони, най-новият първи
GET /sportiva_seasons?is_current=1   → само текущият
```

Публичен — само `saas_key`. Чист масив.

```json
[
  { "id": 1, "name": "2026/27", "year_start": 2026, "is_current": 1, "date_created": "2026-10-29 14:38:33", "date_updated": null }
]
```

Нов сезон се появява сам, когато започне. Точно един е `is_current: 1` —
него ползват всички endpoint-и, когато не е подаден сезон. Миналите сезони
остават — ще служат за архива на класиранията и резултатите.

## 6. Новини — филтри и полета

`GET /blogPosts` е ядреният endpoint (`core-v4-front.md`); тук са само
добавките на проекта. Всички работят и заедно с ядрените параметри
(`limit`, `page`, `tag`, `search`…).

| Параметър | Пример | Какво прави |
|---|---|---|
| `include_children=1` | `?category_id=5&include_children=1` | новините от категорията **и от всичките ѝ подкатегории** (на всяка дълбочина), с обща пагинация. Без него `category_id` е точно тази категория — „БГ Футбол" (5) сама няма новини, те са в подкатегориите ѝ |
| `order_by=views&period=` | `?order_by=views&period=7d` | най-четени за периода: `1d`, `7d`, `30d`. Само новини с поне един преглед в периода, най-четената първа. Прегледите се броят от 2026-10-29 |
| `has_video=1` | `?has_video=1` | новините с видео линк или качен видео файл (`videos` / `video_files`, т. 2), от всички категории |

`?tag=Левски` (ядрен) търси по таговете на новината — частично съвпадение,
т.е. хваща и „Левски Лукойл". Точна връзка новина–отбор ще има по-късно.

Нови и поправени полета на всяка новина:

| Поле | Тип | Значение |
|---|---|---|
| `read_time` | int | минути за четене. **Вече е попълнено** за всички новини (досега беше `0` — ядрото не брои думи на кирилица). `0` само при новина без текст |
| `description_short` | string | първите ~150 знака от текста, без HTML, с „..." накрая. **Винаги попълнено** при новина с текст. Досега беше отрязано по байтове и можеше да завършва със счупен знак |
| `video_thumbnail` | string | корица от YouTube по първия видео линк — за картата, когато новината няма снимка. Празно, ако няма YouTube линк |
| `period_views` | int | прегледите за периода — попълнено **само** при `?order_by=views&period=…`, иначе `0` |

> Видео новините, при които линкът е само в текста (`<iframe>` в `description`),
> **не** влизат в `has_video=1` — за тях видеото трябва да е в полето
> „Видео линкове" на новината.

## 7. Начална страница — всички новини с една заявка

```
GET /sportiva_blog_home
GET /sportiva_blog_home?latest=8&per_category=4&videos=4&most_read=5&period=30d
```

Публичен — само `saas_key`. Заменя отделните заявки за блоковете на
началната страница.

| Параметър | По подразбиране | Значение |
|---|---|---|
| `latest` | 10 | колко последни новини |
| `per_category` | 5 | по колко новини от всяка коренова категория |
| `videos` | 6 | колко видео новини |
| `most_read` | 6 | колко най-четени |
| `period` | `7d` | периодът за най-четени — `1d`, `7d`, `30d` |

Всяка бройка е от 0 до 20; `0` изключва блока (връща празен масив).

```jsonc
{
  "lead": { /* новина — обектът от GET /blogPosts/<id>, или null */ },
  "latest": [ /* новини */ ],
  "categories": [
    {
      "category": { "id": 5, "title": "БГ Футбол", "slug": "…", "position": 1, "active": 1, "parent_id": 0, "url": "…" },
      "posts": [ /* новини от категорията и подкатегориите ѝ */ ]
    }
  ],
  "videos": [ /* новини с видео (has_video=1) */ ],
  "most_read": [ /* новини, най-четената първа; носят period_views */ ]
}
```

| Блок | Какво има |
|---|---|
| `lead` | последната новина, отбелязана като „водеща" (`main_article = 1`); `null`, ако няма |
| `latest` | последните публикувани новини, най-новата първа, **без** водещата |
| `categories` | всяка активна коренова категория (`parent_id = 0`) в реда от админа, с последните ѝ новини — включително от подкатегориите |
| `videos` | последните новини с видео линк или видео файл |
| `most_read` | най-четените за периода |

Новините в блоковете са пълните обекти от `GET /blogPosts` (с `audio`,
`videos`, `images`, `read_time` и т.н.). Една новина може да се появи в
няколко блока.

## 8. Фотогалерии

Проектна версия на ядрения `gallery_categories`. Един албум = една
„категория" на галерията, снимките са в `gallery`.

```
GET /gallery_categories                                    → албумите, най-новите първи
GET /gallery_categories?category_id=5&include_children=1   → албумите от спорта
GET /gallery_categories/<id>                               → албум с всички снимки
```

Публичен — само `saas_key`. Списъкът е с пагинация
(`{ "result": [...], "pagination": {...} }`) и **без снимките** — само
корица и брой. Заявката по `id` връща всички снимки и брои един преглед.

| `description` | string | подзаглавие — под слайдера; може да е празно |
| `slug` / `url` | string | `url` е готовият адрес `/bg/gallery/{id}-{slug}`. При старите албуми `slug` е празен, но `url` пак е попълнен |
| `date_publish` | string | датата на албума — `YYYY-MM-DD HH:MM:SS`. За сортиране и етикета „26.10.2026" |
| `category_id` | int | блог категорията — спортът / първенството; `0` = без категория |
| `views` | int | прегледи |
| `photos_count` | int | брой снимки |
| `cover` | object | корицата — **първата снимка** по реда в албума. Винаги е обект; празен албум → `cover.id` е `0` и `url` е празен |
| `gallery` | array | снимките по реда в албума — **само** при заявка по `id`. В списъка е празен масив |
| `gallery[].image.url` / `url_10x10` | string | снимката и малкото ѝ копие. Има и размери в папки (`800x600/`, `1024x768/`) по същия адрес, като при блога |
| `gallery[].sort` | int | редът в албума (подрежда се с влачене в админа) |
| `page_id` | int | служебно, не се ползва |

Филтри в списъка: `category_id` (+ `include_children=1`), `title`
(частично съвпадение). Ред: най-новите първи по `date_publish`.
